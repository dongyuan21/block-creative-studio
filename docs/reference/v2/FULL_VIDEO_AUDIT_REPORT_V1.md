## 2. 分析方法

### 2.1 全帧机器扫描

对 13,546 帧逐帧计算：

- 全画面、HUD、分数、棋盘、候选区、中心反馈区和终局区的帧差；
- 棋盘亮像素比例与白色扫光比例；
- 候选区颜色质量变化；
- 棋盘和候选区的运动窗口；
- 分数数字变化窗口；
- 暗化终局状态；
- 8×8 单元中心的颜色聚类。

机器输出用于两件事：

1. 保证整段视频没有未覆盖时间段；
2. 找出所有高显著性事件候选，而不是只依赖人工记忆。

机器窗口是候选证据，不等于逐像素人工真值。文件中统一标记为 `machine-candidate` 或 `machine-derived`。

### 2.2 全片人工复核

人工复核覆盖：

- 每 2 秒一帧的整片接触表；
- 按棋盘亮度、中心反馈、分数变化和候选变化选出的 80 个高显著性峰值；
- 第一次完整拖拽、放置、预消除、清除、Great、Combo 的密集帧；
- `NEW HIGH SCORE` 出现前后的密集帧；
- Game Over 和继续卡片出现前后的密集帧。

人工确认的代表事件在 `EVENT_INSTANCE_INDEX_V1.json` 中标记为 `manual-reviewed`。

## 3. 整段分析新增的关键发现

### 3.1 方块不是六色，而是七色

稳定格子聚类与清晰静态帧共同证明存在七个独立颜色族：

```text
coral
amber
lime
cyan
blue
violet
rose
```

旧模型把紫色与玫红合并，导致候选块和牌面资产谱系缺一类。`rose` 必须成为独立颜色 Token。

### 3.2 评价词至少有六级

整片确认的评价词为：

```text
Nice!
Great!
Amazing!
Incredible!
Fantastic!
Unbelievable!
```

旧目录遗漏 `Amazing!` 与 `Incredible!`。六个字形、描边、渐变、装饰和入退场动画都应是独立可替换资产；它们的触发阈值仍属于未解决规则。

### 3.3 存在独立的新最高分演出

当当前分数超过原历史最高分后：

- 左上皇冠数字开始随当前分数继续更新；
- 棋盘中央出现带皇冠的红/粉色 `NEW HIGH SCORE` 横幅；
- 横幅显示新的最高分数值；
- 横幅可与清除、Combo 和后续游戏同时存在。

这不是普通 Praise，也不是只替换一段文字。它包含触发规则、横幅底板、皇冠、标签、数值和独立时间曲线。

### 3.4 候选刷新是复合系统

候选区的新三块出现前后，整片可见：

```text
淡花轮廓
→ 彩色花芯
→ 圆形光晕
→ 花瓣/彩屑
→ 三个 Piece 缩放或显现
```

旧目录只有一个 `tray.refresh-vfx` 黑盒。现在已经拆成五个可独立替换 Atom。

### 3.5 视频中存在调试/测试叠字

整片顶部中央和底部可见极低对比度版本/会话文字。这些是 `capture-only` 原子：分析时保留证据，最终成片默认关闭，不能误当作背景纹理。

### 3.6 最高分不是固定常量

左上数字在本局分数低于历史记录时保持原值；超过记录后随当前分数更新。因此它是：

```text
皇冠视觉资产
+ 数字排版资产
+ max(previousBest, currentScore) 规则绑定
```

不能继续只保存一个固定 `bestScore`。

### 3.7 清除不是单一 VFX

整片中清除至少包含：

```text
预消除行/列填充
行列彩色底层
横向扫光或纵向光柱
亮头与拖尾
光柱内部花朵印记
交叉爆点
格内 5 / 9 / 拇指
格内 Token 动画
方块增亮
方块渐隐/缩小
星形粒子
方形彩屑
花瓣
浮动分数
倍率提示
棋盘边框反应
背景曝光反应
评价词
Combo
```

这些层可以重叠，并且后续输入能够在旧反馈尚未结束时开始。

## 5. 资产谱系的定义

`ASSET_LINEAGE_V2.json` 不再是图片列表。每个 Atom 都区分：

- `visual-asset`：PNG、WebP、SVG、字体或其他实际资源；
- `render-recipe`：Canvas、Shader、材质和合成配方；
- `motion-recipe`：拾取、拖拽、回弹、弹入和退场曲线；
- `particle-recipe`：粒子生成、速度、寿命和层级；
- `rule-binding`：分数、Combo、预消除、评价和高分触发；
- `geometry-asset`：固定机位生产后端中的真实 3D 几何；
- `audio-asset`：与同一事件时间线对齐的声音资产。

每个 Atom 同时记录：

```text
系统是否核心必选
事件发生时是否必选
当前参考档是否必选
是否允许 none
是否可独立替换
依赖项
观测/推断/未解决状态
Reference 2D 表达
固定机位影视表达
可选 Full 3D 表达
视角依赖关系
当前实现状态
```

## 6. 固定机位混合渲染方向

后续生产后端不走“所有东西都变成真 3D”，也不走“所有东西烤成一张伪 3D 图片”。默认分工为：

- 方块主体、大碎片、需要材质一致性的遮挡与阴影：真 3D；
- 棋盘框和格槽：浅 3D 或法线贴图 Sprite；
- 牌面纹样：独立 Decal/Mask；
- 预消除、扫光、边框余辉、背景曝光：Shader/Render Recipe；
- 小碎屑、星光、花瓣：Camera-facing Sprite；
- HUD、分数、格内数字、Praise、Combo、New High Score、终局卡片：Screen 2D；
- 高成本烟雾、花朵或 Hero VFX：可选固定机位预烘焙 Sprite/Flipbook。

摄像机是一级契约，Transform 和镜头参数由 Camera Profile 锁定；仅允许极小的最终画面缩放、平移、震动和曝光反馈。

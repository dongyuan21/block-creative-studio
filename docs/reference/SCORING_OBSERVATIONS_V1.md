# 计分观察与待标定项 v1

## 已确认规则

录像可以直接验证：**放置阶段按新落下的单元逐个给分，每个单元至少 +1。**

| 录像片段 | 方块单元数 | 当前分数变化 |
|---|---:|---:|
| 初始竖条 | 5 | 17 → 22 |
| 随后方块 | 6 | 22 → 28 |
| 随后方块 | 4 | 28 → 32 |

因此实现已经把 `placementPoints` 与 `clearBonusPoints` 拆开，并在落子反馈阶段逐格推动顶部得分。

## 观察到但尚不能还原的数字

- 清除格内出现 `5` 和 `9`。
- 棋盘上出现悬浮 `17`、`33`、`66`、`82`、`99`、`149`、`173`、`393`、`491`、`981`、`2354` 等值。
- `Unbelievable!` 明确配有 `+300`。
- 顶部当前分数在一次清除中可能跨越数百或数千。

单条录像无法判定这些值分别来自：格基础分、一次清除规模、同时行列数、连续清除、历史 Combo、评价奖励、棋盘清空奖励或表现层合并数字。

## 当前代码状态

- `placementPoints`：按方块单元数，已与观察一致。
- `clearBonusPoints`：仍是独立原型公式，用于维持可玩的闭环，**不标记为参考一致**。
- UI/JSON/Replay 已经将两部分分离，下一步可以只替换计分 profile，而不改布局、Replay 或渲染器。

## 下一轮标定方法

需要至少构造并录制以下受控实验：

1. 无 Combo 的单行清除，改变被清格数。
2. 无 Combo 的单列清除。
3. 同时一行一列的交叉清除。
4. 同时两行、三行及更多行。
5. 连续两个回合都清除，与中间断一次清除对比。
6. 棋盘清空与未清空对比。
7. 相同清除结构下替换不同尺寸的落子块。

记录每一帧顶部总分、格内数字、悬浮总数、评价词和 Combo，才能拟合准确公式。

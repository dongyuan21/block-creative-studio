## 结论

参考画面不是“棋盘 + 彩块 + 一个爆炸”三层结构，而是至少五个相互异步的系统：

```text
静态视觉层
+ 交互预览层
+ 落子反馈层
+ 清除演出层
+ 计分/评价/Combo 层
```

下一次输入可以在上一次评价词、边框发光或积分动画尚未完全结束时开始，因此逻辑时间轴不能被一个全屏 VFX 锁死。

## 2D 资产拆分

### 方块

一个方块单元至少拆成：

```text
逻辑占格
基础颜色
方块材质（渐变、边缘、阴影）
牌面纹样（花/叶）
临时落子反馈（高光/拇指）
临时清除覆盖（数字/扫光/消散）
```

牌面纹样不是材质本身，落子后出现的拇指也不是牌面贴图。三者必须能独立替换。候选方块还能逐格使用不同颜色，不应只给整块保存单一 `color`。

### 交互

- 候选块在底部以约 50 px 单元显示。
- 拾取后放大到约 108 px 的棋盘单元尺度。
- 被拖块相对指针上移，避免手指遮挡目标格。
- 合法落点显示逐格半透明预览。
- 该次落子若形成完整行/列，受影响整行/整列提前染色。

### 落子

- 当前分数按新放入的单元数量逐点增长；录像中可确认 `17 → 22` 对应 5 单元，随后 `22 → 28` 对应 6 单元。
- 新单元在短时间内获得边缘发光和拇指/认可反馈。
- 候选块使用状态与视觉落子反馈分开结算。

### 清除

清除是一个阶段序列，而不是一次删除：

```text
预消除整行/列填充
→ 彩色线底
→ 白/粉/青扫光带
→ 逐格 5/9 数字或拇指
→ 星光与彩屑
→ 方块渐隐/缩小
→ 评价词
→ Combo
→ 边框/背景余辉
```

各阶段存在重叠，并且不同强度清除会组合出不同评价词和气氛。

### HUD 和终局

- 左上皇冠数字是历史最高分，与本局当前分数分离。
- 顶部中间为当前分数。
- 右上为图册/Beta 与设置。
- Game Over 后保留暗化棋盘背景，顶部显示 Combo，中央弹出渐变继续卡片。

## 已确认、推断与未解决

### 已确认

- 8×8 棋盘。
- 三个候选块。
- 候选块可逐格多色。
- 放置分数至少包含“每放一格 +1”的阶段。
- 形成完整行/列前有整行/列预填充。
- 清除包含扫光、逐格数字/拇指、粒子、评价词和 Combo 等多个原子。
- 特效允许与后续输入异步重叠。

### 合理推断

- 评价词由一次清除规模、连续清除或 Combo 状态共同决定，而非只由单一行数决定。
- 逐格 5/9 和悬浮 33/66/99/149/393/981/2354 等数字属于多层计分反馈，而不一定都是直接加到当前分数的同一公式项。

### 未解决

- 清除奖励的准确公式。
- Combo 延续/中断的准确窗口与终局 Combo 定义。
- 5 与 9 的逐格数字选择规则。
- 候选块生成概率、保底和难度调节。
- 候选刷新特效的精确时长。
- 各评价词的严格阈值。

当前代码不会把上述未解决项包装成“官方一致”。

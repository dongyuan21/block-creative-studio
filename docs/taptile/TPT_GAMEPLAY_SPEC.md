# TapTile 玩法状态机规格

## 主模式：7 槽三张同面消除

一次点击按以下顺序结算：

```text
输入命中
→ 检查游戏状态、锁定状态和上层遮挡
→ 从棋盘移除该牌（其他牌不坠落）
→ 飞入槽位并插到同面牌之后
→ 更新“选中即计数”的收集目标
→ 同面数量达到 3：先三消，再检查槽位容量
→ 重新计算刚刚解锁的牌
→ 检查警告、失败和胜利
→ 把语义事件交给导演/VFX 层播放
```

这里“先三消，再判满槽”很重要：第 7 张若正好凑成三张，应该有机会消除，而不是在消除前被判失败。

### 槽位归组

新牌不是永远追加在最右边。已有同面牌时，新牌插入该连续同面组末尾；没有同面牌时才追加。示例：

```text
[青蛙A, 熊A]
点击青蛙B
→ [青蛙A, 青蛙B, 熊A]

点击青蛙C
→ [熊A] + match-resolved(青蛙A/B/C)
```

### 遮挡与解锁

- 每张牌保存整数输出像素矩形和非负整数层级。
- 更高层牌与该牌矩形的有效交叠面积达到阈值时，构成一条 `上层 → 下层` 阻挡边。
- 有任意活动阻挡边的牌不可点。
- 点击上层牌后立即重算图；新变为可点的牌通过 `tiles-unlocked` 事件交给表现层。
- 同一层正常视为共面，不互相阻挡。确需同层先后关系时，应拆成不同层，不依赖 DOM 顺序偷渡规则。

## 目标系统

目标独立于三消解析，当前支持：

- `progressOn: selected`：目标牌被点击并进入槽位时计数；符合 `archive04`/心形目标的可观察行为。
- `progressOn: cleared`：牌真正完成匹配清除后计数；为后续玩法保留。

目标达到数量与棋盘清空可以分别配置为胜利条件：`clear-board`、`complete-goals`、`clear-board-or-goals`、`clear-board-and-goals`。基础引擎默认使用“棋盘和槽位都清空”作为严格胜利；广告中的附加金币计数不自动成为硬条件。

由于现有成片没有完整失败样本，V1 将“解析后三消仍未解除的 7/7 判失败”明确标记为**产品决定**，而不是录像已证明的事实。基础状态机当前锁定该决定以保证确定性；实验玩法若需要关闭满槽失败，应使用独立规则配置，不能悄悄改动 V1 的槽位算法。

`fb_competitor` 已直接证明另一个更细的顺序：已有 6 张时，第 7 张若正好补成第三张同面牌，会先消除并继续游戏。因此实现必须是 `插入 → 三消解析 → 对解析后的槽位判满`。

## 两种无槽位变体

### `direct-set-clear`

对应 `tpt971`，点击一张后由系统找到同面集合，直接从原位聚合并清除；没有槽位。默认清除当前棋盘中的全部同面副本，也可以配置成只取 `matchSize` 张。

### `manual-in-place-match`

对应 `chain_clear`，玩家在棋盘原位依次点选同面牌；前两张保持高亮，第三张触发整组清除并留下空洞。当前保底规则为：如果下一张牌面不同，取消上一组高亮并以新牌开始一组；后续拿到更完整录像时可替换这一策略。

## 逻辑事件与表现解耦

纯逻辑只输出语义事件：

- `click-accepted` / `click-rejected`
- `tile-moved-to-tray`
- `in-place-selection-changed`
- `match-resolved`
- `goal-progress`
- `tiles-unlocked`
- `tray-warning`
- `game-won` / `game-lost`

手指移动、牌飞行、槽位挪位、碎裂、评价词、彩屑和音效都订阅这些事件，但不能反向修改玩法结果。这样可以换导演节奏、换特效或固定帧导出，而不需要重新“玩”一遍。

## 模板牌面的打散约束

模板不再按数组顺序连续放置三张相同牌面。生成时先依据真实阻挡图构造一条安全移除顺序，再用固定种子把匹配分组分散到不同位置和层级：

- 同一模板每次打开得到相同结果，保证 Take、回放和导出可复现。
- 每个 `matchKey` 的数量始终是 3 的倍数。
- 不允许在同一排出现三张连续相同牌面的旧式长串。
- 四个内置模板都必须由正式 `safe-win` 求解器完整通关，测试才可通过。

这里的“随机”是可复现的 seeded shuffle，不使用 `Math.random()`，也不会因为刷新页面而改写关卡身份。

## 当前实现

代码位于 `src/taptile/gameplay/`：

- `blockers.ts`：阻挡图与可点击集合。
- `tray.ts`：同面归组和三消。
- `engine.ts`：三种玩法的纯状态转移。
- `types.ts`：状态、规则和语义事件协议。

# TapTile 像素级对齐规范

## 唯一真值坐标

全部 143 条输入成片都是 1080×1920，因此最终输出坐标固定为：

```text
export stage = 1080 × 1920 integer pixels
```

编辑器使用 432×768 的等比例逻辑舞台，X/Y 统一放大 `2.5` 倍即可得到输出像素。旧的 430×764 不是严格 9:16，会让 X/Y 缩放略有差异，已被替换。

```text
authoring 432 × 768
        × 2.5
export   1080 × 1920
```

拖动结束时，坐标量化到 `0.4` 个编辑单位；乘 2.5 后必为整数输出像素。玩法引擎若收到小数输出像素会直接报错，不允许悄悄四舍五入掩盖漂移。

## 牌块几何

每张牌至少保存：

```ts
{
  centerXPx: integer,
  centerYPx: integer,
  widthPx: integer,
  heightPx: integer,
  layer: nonNegativeInteger,
  order: integer
}
```

- 坐标、吸附、视觉绘制和遮挡判定必须使用同一矩形。
- 牌面 PNG 只在这个矩形内部按统一 fit 规则绘制，不能通过透明留白偷偷改变碰撞尺寸。
- 牌体侧壁可以越出正面纹理，但阻挡矩形使用项目约定的“正面可点击区域”，不能拿阴影做碰撞。

## 对齐与吸附

重复结构从一个整数像素原点和 pitch 计算：

```text
x(n) = round(originX + n × pitchX / subdivisions)
y(m) = round(originY + m × pitchY / subdivisions)
```

不要用 `next = previous + roundedPitch` 逐块累加，否则一长排会积累误差。

支持的约束：

- 中心线相等。
- 左/右/上/下边缘相等。
- 两牌中心缝线。
- 连续牌等距。
- 半格/四分之一格层叠轨道。
- 同组选中牌保持刚体相对位移。

## 浏览器绘制

- 舞台保持 9:16，预览只允许统一 scale，不允许 X/Y 分别 stretch。
- 最终导出时直接把内部舞台设为 1080×1920；不要从截图尺寸反推。
- 同一行牌块最终 `top/bottom` 差必须为 0 px；同一列 `left/right` 差必须为 0 px。
- 层级排序用 `(layer, order)`，玩法阻挡用 `layer + 矩形交叠`，两者必须来自同一数据。
- 图片纹理按设备像素解码，禁用会改变几何尺寸的隐式 border/padding。

## QA 闸门

导出前自动检查：

1. 所有输出中心与宽高均为整数。
2. 432×768 到 1080×1920 的 X/Y scale 都是 2.5。
3. 同一对齐组边缘离散差为 0 px。
4. 等距组 gap 的最大值减最小值为 0 px。
5. 阻挡图无自环，层级边只从高层指向低层。
6. 可点击态与实际点击判定使用同一阻挡图。
7. 1080×1920 固定帧截图与预览同状态叠图检查无 1 px 漂移。

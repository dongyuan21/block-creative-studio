# TapTile 关键证据时间点

时间点来自无水印原版成片，精度用于定位与复核，不作为逐帧导演定时的最终标定值。2026-09-03 的复核只使用 8 条 `tray-match-3` 原版，不把 132 条换牌版重复计算为独立玩法证据；先对每条成片做 1 fps 全程槽位时间线，再对关键转折抽取原始 1080×1920 帧。

## 8 条七槽原版的证据边界

| 源组 | 槽位构图 | 基础玩法证据 | 仅属于该素材的扩展表现 |
|---|---|---|---|
| `archive01` | 顶部 7 个独立槽 | 连续三张同面进入后清除；棋盘原位留空 | 糖果皮肤、评价词 |
| `archive02` | 顶部 7 个独立槽 | 三消、上层移除后解锁、无重力 | 航海皮肤 |
| `archive03` | **底部** 7 个独立槽 | 核心仍是入槽三消、无重力 | 底槽只是构图变体；黑底/粒子为烘焙表现 |
| `archive04` | 顶部 7 个独立槽 | 入槽三消与棋盘遮挡 | 三叶草 `0/9` 收集目标、牌背 |
| `fb_competitor` | 顶部 7 个独立槽 | 6 槽状态下第 7 张凑三消后继续游戏 | 评价词、碎裂风格 |
| `latest_competitor` | 顶部 7 个独立槽 | 入槽三消、无重力 | 心形目标、金币、问号、`×2`、大金币遮挡物 |
| `tpt760` | 顶部 7 个独立槽 | 密集多层也遵守同一套三消、归组和 6/7 预警 | 底部道具、粉色牌体 |
| `tpt811` | 顶部 7 个独立槽 | 归组插入、三消、覆盖禁点、6/7 预警、无重力 | 底部储备排、教学文案 |

`archive03` 证明槽位在屏幕顶部还是底部属于呈现参数，不应改变结算顺序。本 Studio V1 选择 `tpt760`/`tpt811` 的顶部构图作为固定预览基准。

## 可以锁定与不能冒充证据的规则

| 结论 | 等级 | 实现约束 |
|---|---|---|
| 槽位容量为 7，且空槽始终是 7 个独立格 | 视频直接观察 | DOM、Canvas、飞行落点共用同一 7 槽几何 |
| 点击牌从棋盘移除，其他牌不发生重力位移 | 8 组一致观察 | 状态只删除被点 ID，不重排棋盘坐标 |
| 高层有效覆盖会阻止点击；同层不是先后队列 | 视频直接观察 + 几何建模 | 只建立高层到低层的阻挡边 |
| 新牌归到同面组后面 | `tpt811` 直接观察 | 有同面时插组尾，无同面时追加 |
| 第三张立即移除三张同面牌 | 8 组一致观察 | 插入后立即解析一组三张 |
| 第 7 张若正好凑三消，不应先判失败 | `fb_competitor` 直接观察 | `insert → match → capacity`，顺序不可交换 |
| 6/7 出现预警 | `tpt760`、`tpt811` 直接观察 | 仅未终局且解析后仍为 6 张时发警告 |
| 未解决的 7/7 判失败 | **产品决定；样本未展示完整失败** | V1 默认启用，但文档和 UI 不宣称是录像实证 |
| 棋盘与槽位同时为空判胜 | 产品决定，与胜利尾段一致 | 基础 V1 的确定性终局条件 |
| 目标、金币、问号、`×2` | 仅扩展素材证据 | 不进入 V1 基础状态机，除非单独定义扩展规则 |

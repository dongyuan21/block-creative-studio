# TapTile 持续优化与 Blender 闭环计划 V1

更新时间：2026-09-04
执行范围：仅本地实现与验证，不推送远端。

下一阶段量化门槛见 [`TAPTILE_NEXT_PHASE_GATES.md`](./TAPTILE_NEXT_PHASE_GATES.md)。

## 1. 最终目标

把当前可编辑、可试玩、可回放、可导出的 TapTile Studio，逐步提升为同一份确定性时间线驱动的创意生产工具：

1. 编辑器中的牌面、层级、槽位和导演效果与最终视频逐帧一致；
2. 自动试玩在任意合法牌量下尽可能多消除，并能解释、取消和复现搜索结果；
3. 1080×1920、30fps 导出不仅改变码率，还拥有可量化的画质、性能和稳定性档位；
4. 2D、浏览器 3D 与 Blender 共用明确的空间、相机、时间和资产合同；
5. 跑通 `BCS 场景交换包 → Blender 后台导入/渲染 → GLB/透明帧/报告 → BCS 回读` 的最小闭环；
6. 最终允许 Blender 生产的牌块、碎片和 3D 消除效果进入固定机位预览与视频导出，而不是停留在“文件已保存但不可见”。

## 2. 当前基线

### 已可用

- TapTile 规则、遮挡、7 槽位、先三消再判满、确定性 Take 和导演时间线；
- Reference 2D Canvas 预览与固定帧 MP4 导出共用 RenderJob；
- 1080×1920、30fps 规格锁定；
- 最大消除搜索可生成部分成功 Take；
- Browser Asset Store 能按 SHA-256 保存图片、音频和自包含 GLB；
- Three.js 旧玩法已有真实几何、材质、灯光、Bloom、碎片和粒子实现，可抽取经验；
- 本机 Blender 5.2.1 LTS 可后台运行，具备 EEVEE、Cycles、GLTF 导出、FFmpeg 和 OpenEXR 支持。

### 当前剩余断点

- 浏览器端已经能把 Blender VFX 叠加进同一预览/导出 RenderJob，但还没有可视化编辑 Blender 配方参数；
- `cinematic` 已使用 1.5× 真超采样并做编码后像素复验，长视频内存峰值与分段编码仍需压力测试；
- anytime 最大消除搜索可取消、可回传最佳解，但尚未迁移到 Worker，极大关卡仍会占用部分主线程时间片；
- Blender 专用 VFX GLB 已做到零贴图、稳定语义 ID 和精确时间线，透明 HDR、景深和运动模糊仍需要单独的合成策略；
- 完整 UI、手势、音频和 3D 特效已在浏览器终片合成；Blender 侧完整 Take 的断点续渲、缓存和批量农场仍未实现。

## 3. 迭代原则

- 每轮只承担一个可测风险，先建立失败测试或验收样例，再实现，再做浏览器/CLI/Blender 实机验证；
- 预览和导出必须消费同一个冻结 RenderJob，禁止复制一套“看起来相似”的效果逻辑；
- 外部 DCC 产物先编译成受限运行时资产，浏览器绝不解释任意 `.blend`；
- Blender 原工程只读，所有规范化和渲染都写入独立输出目录；
- 结构检查优先使用最低成本路径，LookDev 使用 EEVEE，只有明确需要光追时才升级到 Cycles；
- 遇到单一路线不通，保留证据并切换到 GLB、Transform Track 或透明 Flipbook 中更合适的一条。

## 4. Blender 交换合同（第一版）

### 输入

`scene-exchange.json` 至少声明：

- 合同版本、生成器版本和确定性 seed；
- 设计分辨率、fps、帧区间和 Straight Alpha；
- 坐标约定：右手系、米、Z-up；
- 固定相机与画面安全区；
- 每个实体的稳定 id、语义角色、变换、尺寸、材质和可选面图引用；
- 每个三消事件的帧、槽位、中心点、强度和期望输出角色。

### Blender 编译产物

```text
compiled/<package-id>/
├── source-artifact.json
├── compile-report.json
├── scene.normalized.blend
├── scene.glb
├── scene.vfx.glb            # 终片叠加专用：固定相机 + match VFX，零牌面贴图
├── preview.png
├── representative-frames/
└── effects/                 # 后续：透明序列/Transform Track/碎片 GLB
```

`compile-report.json` 必须记录 Blender 版本、实际渲染引擎、分辨率、fps、相机、对象数、三角形数、材质数、动画范围、输出哈希、耗时、警告和错误。只有报告通过，资产才允许进入 BCS。

### 第一条竖切

1. BCS 生成包含固定相机、舞台、三张槽位牌和一次 match 事件的交换包；
2. Blender 后台脚本导入交换包，创建确定性 EEVEE 场景；
3. 输出规范化 `.blend`、self-contained GLB、中性预览和机器报告；
4. BCS CLI 验证所有文件、哈希、GLB 2.0、画面规格和预算；
5. 再将 GLB/透明效果帧接入 TapTile 固定机位 Render Pass。
